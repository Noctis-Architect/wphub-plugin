# HubPilot

پلاگین اتصال وردپرس به کنسول WP-Hub؛ آمار محلی و بدون کوکی، بررسی امنیتی ساده، و نمایش وضعیت سرعت، امنیت و پایش در یک داشبورد.

A WordPress connector for the WP-Hub console with local cookie-free analytics, basic security checks, speed/security/uptime status, and optional cloud sync.

> **کنسول WP-Hub** — آمار، سرعت، امنیت و پایش سایت در یک داشبورد.
> **[شروع رایگان در console.wp-hub.org](https://console.wp-hub.org)**

---

## چرا HubPilot؟

- **اتصال به کنسول**: وضعیت تست سرعت، امنیت و پایش را از کنسول WP-Hub داخل وردپرس نشان می‌دهد.
- **بررسی امنیتی ساده**: دایرکتوری، REST users، wp-admin، افزونهٔ امنیتی، ویرایش فایل و دیباگ را در یک کارت کم‌حجم چک می‌کند.
- **سبک و بدون کوکی**: بدون اسکریپت سنگین، بدون کوکی ردیابی و بدون بار اضافه بر دیتابیس.
- **آمار قابل اعتماد**: علاوه بر User-Agent، سیگنال‌های رفتار مرورگر (webdriver، WebGL، پلاگین‌ها، rAF، تعامل و زمان لود) بررسی می‌شوند.
- **آمار چندحالته**: حالت پیش‌فرض فقط بازدیدهای «تأییدشده» را نشان می‌دهد؛ حالت‌های «همه»، «بدون JS» و «مشکوک» هم در دسترس‌اند.
- **محلی یا ابری**: می‌توانید همه‌چیز را روی همان سایت نگه دارید یا برای گزارش‌های کامل به کنسول وصل شوید.
- **حریم خصوصی**: در حالت محلی IP خام ذخیره نمی‌شود؛ بازدیدکننده فقط با هش روزانه شناسایی می‌شود.

## کنسول WP-Hub

پلاگین به‌تنهایی هم کار می‌کند، اما با اتصال به کنسول WP-Hub داده‌های بیشتری در یک داشبورد جمع می‌شوند:

- آمار بازدید، بازدیدکننده، نشست، نرخ پرش و زمان تعامل
- تفکیک کیفیت ترافیک: تأییدشده، بدون JS، مشکوک و دیتاسنتر/Tor/VPN
- تست سرعت موبایل و دسکتاپ
- تست امنیت و وضعیت SSL
- پایش آپ‌تایم و هشدارها

برای شروع، در [کنسول WP-Hub](https://console.wp-hub.org) یک حساب بسازید، دامنه را تأیید کنید و **کلید اتصال سایت** را دریافت کنید.

> آدرس کنسول در پلاگین **ثابت و هاردکد** است. در تنظیمات پلاگین فقط **کلید اتصال** را وارد می‌کنید؛ هیچ فیلد آدرسی وجود ندارد.

## ویژگی‌ها

- تشخیص ربات در چند لایه:
  - User-Agent (موتورهای جستجو، ابزارهای HTTP، headless، مانیتورینگ و…)
  - سیگنال‌های مرورگر شبیه Google Analytics (اجرای JS، رفتار صفحه، رندر WebGL، پلاگین‌ها، rAF، تعامل کاربر)
- چهار حالت گزارش: `verified` (پیش‌فرض)، `all`، `nojs`، `suspect`
- کارت کیفیت بازدید و تفکیک سهم هر گروه
- ذخیره‌سازی محلی با نگهداری پله‌ای (جزئیات، روزانه، خلاصه)
- ارسال ابری با gzip، HMAC-SHA256، صف موقت و backoff
- بدون کوکی و بدون ردیابی شخصی

## نصب

1. فایل ZIP نسخهٔ انتشار را از بخش Releases دانلود کنید (یا پوشهٔ `hub-pilot` را از همین مخزن بردارید).
2. در وردپرس به **افزونه‌ها ← افزودن** بروید و ZIP را نصب و فعال کنید.
3. به **آمار WP-Hub ← تنظیمات** بروید.
4. حالت ذخیره‌سازی را انتخاب کنید:
   - **محلی**: داده‌ها روی همان سایت می‌مانند.
   - **ابری**: فقط کلید اتصال سایت را از کنسول وارد کنید.

## تنظیمات اتصال ابری

- **فقط کلید اتصال** در پنل وجود دارد؛ آدرس کنسول قابل ویرایش یا نمایش نیست و در کد ثابت است.
- ارسال با `Authorization: Bearer` و امضای HMAC انجام می‌شود.
- برای نسخهٔ خودمیزبان یا محیط توسعه، می‌توانید آدرس کنسول را به‌صورت ثابت در `wp-config.php` تعریف کنید:

```php
define( 'WPHS_CONSOLE_URL', 'https://your-console.example' );
```

این کار فقط برای توسعه/خودمیزبانی است و در پنل نمایش داده نمی‌شود. در نسخهٔ عمومی، پیش‌فرض `https://console.wp-hub.org` است.

### زمان‌بندی ارسال

پلاگین از WP-Cron هر ۵ دقیقه استفاده می‌کند. اگر سایت ترافیک کمی دارد یا `DISABLE_WP_CRON` فعال است، یک کرون واقعی روی سرور تنظیم کنید:

```bash
*/5 * * * * wp cron event run wphs_cloud_sync --path=/path/to/wordpress
```

یا مستقیماً `wp-cron.php` را با PHP اجرا کنید. بدون کرون واقعی، ارسال ابری ممکن است با تأخیر انجام شود (این محدودیت خود WP-Cron است، نه پلاگین).

## حالت‌های آماری

| حالت | معنی |
|---|---|
| `verified` (پیش‌فرض) | User-Agent سالم + تأیید رفتار مرورگر؛ بدون دیتاسنتر |
| `all` | همه بازدیدها شامل تأییدشده، بدون JS، مشکوک و دیتاسنتر |
| `nojs` | User-Agent سالم اما بیکن JS دریافت نشده |
| `suspect` | رفتار مرورگر رد شده یا IP دیتاسنتر/Tor/VPN بوده |

در حالت ابری، تشخیص دیتاسنتر/Tor/VPN در کنسول انجام می‌شود. اگر گزینهٔ ارسال IP فعال باشد، IP فقط برای همین تشخیص به کنسول می‌رود و در دیتابیس کنسول ذخیره نمی‌شود.

## حریم خصوصی

- در حالت محلی، IP خام یا User-Agent خام ذخیره یا ارسال نمی‌شود.
- بازدیدکننده با هش روزانه (IP + UA) شناسایی می‌شود و هش هر روز عوض می‌شود.
- در حالت ابری، IP بازدیدکننده فقط در صورت فعال‌بودن گزینهٔ «ارسال IP به کنسول» و فقط برای تشخیص شبکه ارسال می‌شود.
- DNT/GPC قابل احترام است و کاربران واردشده به‌صورت پیش‌فرض ردیابی نمی‌شوند.

## نیازمندی‌ها

- WordPress 6.0 یا بالاتر
- PHP 7.4 یا بالاتر
- برای حالت ابری: دسترسی HTTPS خروجی به کنسول و یک کرون واقعی (توصیه‌شده)
